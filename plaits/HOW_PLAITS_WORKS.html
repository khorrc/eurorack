How Plaits works, at code level

A guide for readers who know some Python but not C++. Links point to the code at commit 54b4961 of this fork, so line numbers stay valid. The linked source files (engine.h, voice.cc, virtual_analog_engine.h/.cc, variable_saw_oscillator.h, variable_shape_oscillator.h) carry extra [Plaits guide] comments on this branch; the code itself is unchanged.

C++ for Python readers

  • .h and .cc files. A .h header declares a class and its fields. A .cc file holds the method bodies. Small methods often sit in the header, which is where the oscillators live.
  • class Foo : public Engine means Foo inherits from Engine. virtual ... = 0 marks an abstract method that every engine must implement.
  • float* out and size_t size are a pointer to an array of floats plus its length. Think of a NumPy buffer filled in place. Nothing is returned.
  • &x passes a reference, so the callee can modify x. const means read-only.
  • #if VA_VARIANT == 2 is compile-time selection, like deleting the other branches before the program is built.
  • template<bool enable_sync, ...> generates a separate copy of the function per flag combination, so the if (enable_sync) check costs nothing at runtime.
  • No dynamic memory. The firmware runs on a small STM32. Init() plays the role of __init__, and buffers come from a BufferAllocator arena.

Signal flow for one block

The sample rate is 48 kHz and the block size is 12 samples (dsp.h). Everything is processed in blocks of 12. Voice::Render does this each block:

  1. Trigger handling. Detects the rising edge and fires the decay and LPG envelopes.
  2. Engine selection. The ENGINE knob plus CV goes through a quantizer to give an index.
  3. Parameters. ApplyModulations (e.g. note, timbre, morph) combines knob, attenuverter, patched CV and the internal decay envelope. The result is an EngineParameters struct with note, timbre, morph, harmonics, accent, trigger. That struct is the whole interface between module and engine.
  4. e->Render(...) fills two 12-sample buffers, out and aux.
  5. Post-processing. The low-pass gate and gain are applied (LPG, out, aux), then the result goes to the OUT and AUX jacks.

Every engine implements the abstract Engine class (Init, Reset, LoadUserData, Render). In Python terms, voice.cc is a loop calling engines[i].render(params, out, aux). Engines are registered in a fixed order through the EngineRegistry. Each registration sets output gains and an already_enveloped flag. Drums and strings set that flag because they shape their own amplitude, so the LPG is bypassed.

The Virtual Analog engine

Files: dsp/engine/virtual_analog_engine.h and dsp/engine/virtual_analog_engine.cc.

It has four oscillator members: primary_, auxiliary_ and sync_ are VariableShapeOscillators, and variable_saw_ is a VariableSawOscillator.

The Render function has three #if VA_VARIANT branches. The header sets VA_VARIANT 2, so variant 2 is the one compiled. The other variants map the same parts differently.

Frequencies

NoteToFrequency (engine.h) turns the note into a normalised frequency, meaning the phase increment per sample. ComputeDetuning(harmonics) maps the HARMONICS knob to an interval for the second oscillator. It interpolates between the stops 0, 7, 12, 19, 24 semitones, with Squash applied twice. Squash is a smoothstep, so the knob dwells near each musical interval. The sign lets it go downward too.

OUT = square + saw

  • The square comes from sync_.Render(...). TIMBRE sets its pulse width, and above 0.5 it also sets the hard-sync ratio.
  • The saw comes from variable_saw_.Render(...). MORPH moves it from a notched saw through a plain saw to a triangle-like shape.
  • The two are summed with gains square_gain and saw_gain, divided by norm so loudness stays roughly constant.

AUX = "monster sync"

primary_ and auxiliary_ each run with a sync frequency that rises with TIMBRE², up to 48 semitones. AUX is half of their difference.

Oscillators and anti-aliasing

  • Each oscillator keeps a phase_ that ramps 0 to 1, adding frequency every sample.
  • The waveform is computed naively from the phase in ComputeNaiveSample (saw, shape).
  • Wherever the waveform has a discontinuity (phase wrap, pulse edge, sync reset), the code adds a correction from ThisBlepSample / NextBlepSample and their integrated versions (example). This is PolyBLEP, a small polynomial that removes aliasing.
  • A correction can spill into the following sample, which explains next_sample_. Each loop writes this_sample and carries the leftover forward.

Smoothing and hard sync

  • ParameterInterpolator ramps a value linearly across the 12-sample block from its previous value, avoiding zipper noise. The previous value lives in a member, which is why &frequency_ is passed in.
  • Hard sync has a master and a slave phase. When the master wraps, the slave resets. The code computes the sub-sample time of the reset (reset_time) so the BLEP lands at the exact position.
